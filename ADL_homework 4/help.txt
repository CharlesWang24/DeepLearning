Understanding the Data

Each _info.json file contains a dictionary with information about 10 images.

track is the track name

karts is a list of kart names

For detections (see the draw_detections function for a clearer picture), you get:

class_id:  class_id == 1 means the object is a kart

track_id: the kart's id, used to look up its name in the karts list

coordinates x1, y1, x2, y2

The ego car is the one closest to the center of the image.

To find the ego car, calculate the distance from each kart/box to the center of the image. How you calculate that distance is part of the homework, but recall the two common options: Euclidean distance and Manhattan distance. Which one do we want here?

In this part, it's also important to analyze the data. For example, do you see cases with zero karts, or with 0 as the answer?

For generate_qa.py

To check the quality of your data, use generate_qa.py to generate questions and answers from the validation data, then compare the results against data/valid_grader/balanced_qa_pairs.json.

For every entry in balanced_qa_pairs.json that shares the same question and image_file with your generated data, the answer must match too.

You can write a Python script to check this easily.

Make sure your questions and answers follow the same format as those in balanced_qa_pairs.json.

Note: Do not train on the validation data. Use it only to check the quality of your data.
We generated approximately 296k QA pairs.

For finetune.py

Make sure the model is saved under vlm_model, not vlm_sft.

Epochs number: 

If your dataset is good, 0.05 epochs (or ~15k paired samples) can be just enough to get full points on Part 1. You can experiment with training longer to achieve better performance and get a larger margin for error.

For generate_captions.py

For this part, we recommend first confirming that generate_qa.py runs without errors, since you'll likely reuse some of its data-generating logic. 

Then apply the same logic to validate your data against data/valid_grader/all_mc_qas.json, which holds one correct caption per image. For each image_file, the result counts as correct if that image's correct caption appears in your generated data.

You can write a Python script to check this easily.

Note: Do not train on the validation data. Use it only to check the quality of your data.
We generated approximately 270k captions.

For clip.py

Make sure the model is saved under clip_model, not clip.

Here τ is a fixed number set to 0.07, and CS is the cosine similarity.

In the CLIP paper, the authors make the temperature learnable. The problem is that during training, the optimizer could push τ toward zero or even negative values, which would break the softmax. To avoid this, they don't learn τ directly. Instead, they learn a parameter τ and use  e^τ_learnable as the scale on the logits, as shown in the pseudocode from the CLIP paper.

Now solve for τ_learnable to find its initial value.

Loss:

You don't need to use labels that is passed to that function and instead create your own labels following the pseudo code from the paper.

Idea behind this: your logits are of shape (B, B). Each row in that tensor is logits for one image. For example, the first row is logits for image 0. The correct label is always on the diagonal of this (B, B) matrix. That is, for image 0, the correct label is 0: that is why creating the labels that are 0,1,2,3,... works in this case. Since we are focusing on the rows, axis=0 is correct. loss_i in pseudo code represents image to text loss (considering all possible texts for one image).

Each column of the (B,B) matrix has logits for text. The reasoning is similar, but now we are considering columns instead of rows, and that's why axis=1. loss_t in pseudo code corresponds to text to image loss (considering all possible images for one text). 

Epochs number: 

0.05 epochs (or 14k paired samples) should train relatively fast on GPU and should result in validation accuracy about 40% (for a quick check if you are on the right track). 

0.10 epochs should bring the accuracy to about 68%. 

To get to the required accuracy, increase the epochs value further (Set it to 0.25 or higher). 

For all of these results, the batch was set to 64. If you would like to use higher batch, the epochs number will have to be higher as well.
